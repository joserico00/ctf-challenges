# CTF Challenges

A set of beginner-to-intermediate Capture The Flag challenges that I designed and built for hands-on cybersecurity workshops and cyber camps. Each challenge teaches one concrete skill: classical ciphers and encodings, hashing, file and image forensics, core Linux commands, log analysis, basic Python debugging and network traffic artifacts. Many challenges come with the Python or C build script I used to make them, so they can be rebuilt and re-randomized for a new group.

Solutions and flag values are intentionally **not** included (see [Solutions are not included](#solutions-are-not-included)). Every flag in the scripts is a placeholder such as `cybercamp{your_flag_here}`, and files generated from those scripts are not committed. Organizers set their own flags and then build the challenges (see [Building / hosting the challenges](#building--hosting-the-challenges)).

- **Audience:** beginners, from first-time terminal users up to students who have done a few CTFs
- **Size:** about 37 challenges across 7 populated categories, plus placeholder folders for planned categories
- **Flag format:** mostly `cybercamp{...}`. A few older challenges use `camp{...}`, `CYBERCAMP{...}` or `CTF{...}`. The scripts ship with placeholder values in these formats.
- **Language:** challenge text is mostly English. A few hints, comments and practice files are in Spanish.

## Cryptography

Ten static challenges. Each file holds a single flag-formatted string run through one encoding or cipher. No build scripts; the files are the challenges.

| Challenge | What the player gets | Concept | Difficulty |
|---|---|---|---|
| **A1Z26** | A line of space-separated numbers from 1 to 26 | Each letter is replaced by its position in the alphabet. Introduces substitution. | Easy |
| **Caesar** (`Ceasar/ceasar`) | One line of uppercase letters that keeps the `prefix{...}` flag shape | Caesar/ROT-N shift with an unknown shift. Players learn that 25 possible keys can simply be tried one by one. | Easy |
| **ASCII** | Space-separated decimal numbers | Characters stored as their decimal ASCII code points | Easy |
| **Decimal** | Space-separated decimal numbers | Same representation as ASCII, with a different message. Good for reinforcing the idea. | Easy |
| **Binary** (`binarytext`) | Groups of 7 binary digits | Binary-encoded ASCII. Covers bits, bytes and why the groups are 7 digits long. | Easy |
| **Base64** | A single Base64 string | Recognizing Base64 by its character set and decoding it (`base64 -d`, CyberChef) | Easy |
| **Bacon** | Groups of five `0`/`1` symbols | The Baconian cipher, where each letter is a 5-symbol group. It looks like binary, so players have to tell the two apart. | Easy-Medium |
| **Morse** (`morse_code/encode.txt`) | Dots and dashes, with wider gaps between words | Morse code | Easy |
| **Vigenère** | A short flag-shaped ciphertext plus `info.txt`, a Spanish-language "investigation note" that provides the key | Polyalphabetic substitution. Players use the recovered key instead of treating it as a Caesar shift. | Easy-Medium |
| **Hash** (`md5/encoded.txt`) | A single hexadecimal hash digest | Identifying the hash algorithm from the digest, then recovering the input with a wordlist or hash-lookup service. Shows why unsalted hashes of common strings are weak. | Medium |

## Forensics

### AES: `Forensics/aes/`
- **Skill:** symmetric encryption. Covers AES in CBC mode, what the key and initialization vector (IV) do, PKCS#7 padding, and Base64 for sending binary ciphertext.
- **Player gets:** the Base64 ciphertext printed by the builder, plus whatever key material the facilitator decides to give out.
- **How it's built:** `aes.py` uses PyCryptodome to encrypt the `flag` string set at the top of the script (a placeholder until you replace it) with a fixed 16-byte key and a fixed 16-byte IV (`AES.MODE_CBC`), pads it to the block size and prints the Base64 result. The ciphertext is not stored in the repo; it is produced when the script runs.
- **Difficulty:** Medium

### Dictionary attack: `Forensics/dictionary/`
- **Skill:** password cracking with a wordlist, and why fast, unsalted hashes like plain SHA-256 are unsafe for passwords.
- **Player gets:** `dictionary.txt` (a wordlist) and `hashed_password.txt` (a SHA-256 hex digest), both generated by the organizer with `dic.py` (neither file is committed). The goal is to find the wordlist entry that produces the hash, using a short script, `hashcat` or John the Ripper.
- **How it's built:** `dic.py` generates 1,000 random 5-letter strings (`random.choices(string.ascii_letters, k=5)`), adds the chosen password to the wordlist and writes the password's SHA-256 digest to `hashed_password.txt`. The chosen password in the script is a placeholder 8-letter word, with a comment telling you to replace it. Parameters are the decoy count, decoy length and the chosen word.
- **Difficulty:** Easy-Medium

### MD5 file match: `Forensics/md5sum/`
- **Skill:** file integrity checking. Players compute hashes with `md5sum`/`md5` and match one against a given value.
- **Player gets:** `cybercamphashes/file1.txt` to `file10.txt` (100 random characters each) and a target MD5 value from the facilitator.
- **How it's built:** `md.py` recreates `cybercamphashes/`, fills 10 files with random alphanumeric text, picks one file at random and prints its MD5 digest. That printed digest is the challenge prompt and is not saved to disk. The committed `file*.txt` files are a sample set; running `md.py` regenerates all of them. No answer key is included.
- **Difficulty:** Easy

### Photo geolocation: `Forensics/forensic phtoot/`
- **Skill:** image metadata forensics. Players read EXIF data with `exiftool` or an online viewer, pull out GPS coordinates and work out where a photo was taken. It also shows how much a photo can reveal about its owner.
- **Player gets:** six JPEG photos (`aroundtheworld`, `iliketurtles`, `memories`, `snake`, `station`, `whenyouwishuponastar`). Five contain an EXIF GPS block. `snake.jpeg` has camera metadata but no GPS block, so it needs other clues.
- **How it's built:** static photos, no build script.
- **Difficulty:** Easy-Medium

### Geocodes: `Forensics/geocodes/gecode1.txt`
- **Skill:** reading latitude/longitude and turning it into a place name with a map or reverse geocoding.
- **Player gets:** one coordinate pair.
- **Difficulty:** Easy

### Strings: `Forensics/stri.c`
- **Skill:** static analysis basics. Compiled programs still carry their string literals, and `strings` or a hex viewer can pull them out.
- **Player gets:** a binary named `flag_finder` that the organizer compiles from `stri.c`. When run, it only prints a greeting.
- **How it's built:** `stri.c` declares the flag (a placeholder until you set your own) in a character array that is never printed. No compiled binary is committed; compile it with, for example, `cc stri.c -o flag_finder` on the platform players will use. `Forensics/strings/` is an empty placeholder.
- **Difficulty:** Easy

## Linux commands

### Flag hunt: `Linux commands/ctfmaker.py`
- **Skill:** navigating a directory with `find` and `ls -a`, understanding hidden dotfiles, searching file contents (`grep -r`) and counting files (`ls -a | wc -l`).
- **Player gets:** the `ctf_challenge/` directory generated by the script, and three tasks the script prints:
  1. find a file with a given name,
  2. find the file whose contents include a given phrase,
  3. count the files in the flags directory and submit the count in the stated flag format.
- **How it's built:** `ctfmaker.py` deletes any existing `ctf_challenge/` (`shutil.rmtree`), recreates `ctf_challenge/flags/`, writes the flag files (hiding at least one of them as a dotfile) and prints the task descriptions. Both flag files use a placeholder value that you replace before building. The generated `ctf_challenge/` folder is not committed.
- **Difficulty:** Easy

### `find` mazes: `Linux commands/find/`
- **Skill:** searching recursively with `find` (by name, including hidden files) instead of opening directories one at a time.
- **Player gets:** a base directory generated by `genereate.py`, containing `dir0` to `dir99`, one of which holds the flag. Neither maze is committed.
  - **Level 1** (`ctf_challenge/`): the flag file has a normal name.
  - **Level 2** (`ctf_challengelevel2/`): the flag file is a dotfile, so a plain `ls` won't show it.
- **How it's built:** `genereate.py` removes the previous base directory (`rm -rf`), creates `num_dirs` (100) directories named `dir0` to `dir99`, picks one with `random.randint` and writes a hidden flag file (placeholder content until you set your flag) into it. As written, the script builds Level 2. Level 1 comes from the same approach with base directory `ctf_challenge` and a non-hidden file name. Parameters are `base_dir`, `num_dirs`, and the flag file name and content.
- `find/level/` and `find/2/` are empty placeholders.
- **Difficulty:** Easy (both levels; Level 2 adds the hidden-file twist)

### `grep`: `Linux commands/grep/`
- **Skill:** pattern searching with `grep` (including `-o` for matched text only) on a file too large to read by eye.
- **Player gets:** `challenge.txt`, about 780 KB of filler words with the flag hidden among them. It is generated by `generategrep.py` and not committed.
- **How it's built:** `generategrep.py` picks 100,000 words at random from a 26-word list of fruit and food words, inserts the flag (set in the script; a placeholder until you replace it) as one extra word at a random position and writes `challenge.txt`.
- `workshop2.txt` is a tiny two-line Spanish practice file for a first run of `grep` during the workshop.
- **Difficulty:** Easy

### `file`: `Linux commands/file/`
- **Skill:** using `file` (magic-byte detection) to find a file's real type before opening it, instead of trusting its extension.
- **Player gets:** `cat.png`, a file named like an image that is really plain text containing the flag.
- **How it's built:** the file is not committed. The organizer creates it in `Linux commands/file/` with one command, for example `echo 'cybercamp{your_flag_here}' > cat.png` (using your own flag).
- **Difficulty:** Easy

### `tar`: `Linux commands/tar/`
- **Skill:** listing and extracting gzip-compressed tar archives (`tar -tzf`, `tar -xzf`) and recognizing `.tar.gz` files.
- **Player gets:** `flag.tar.gz`, an archive containing a single text file.
- **How it's built:** neither the archive nor its source text file is committed. The organizer creates the archive in `Linux commands/tar/` with one command, for example `echo 'cybercamp{your_flag_here}' > flag.txt && tar -czf flag.tar.gz flag.txt && rm flag.txt` (using your own flag).
- **Difficulty:** Easy

## Scripting / Programming: `Scripting-Programming/python/`

Twelve short Python programs for students who have never programmed. Each one prints its flag once the program runs and its logic is correct. Several include comments that point to the line to look at. In most levels players read, run and fix the code; in a few (such as pass07) reading the source is enough.

The flags in the scripts are placeholders (`cybercamp{your_flag_here}`, or `CTF{your_flag_here}` in pass07), so replace them with your own before an event. Keep each level's mechanics when you do: `pass04.py` and `pass06.py` spell the flag as a list of characters or parts, and `pass08.py` pads it with extra `1`s that players have to strip.

| Script | Concept | Difficulty |
|---|---|---|
| `pass01.py` | Running a Python script for the first time | Easy |
| `pass02.py` | Boolean variables and `if`/`else` branches | Easy |
| `pass03.py` | `while` loops, counters and variable initialization (Spanish comment) | Easy |
| `pass04.py` | Indexing a list of characters inside a loop, loop bounds | Easy |
| `pass05.py` | Variables and choosing what gets printed | Easy |
| `pass06.py` | `for` loops and `range()` bounds | Easy |
| `pass07.py` | Password prompt with `getpass`: reviewing source code for hardcoded secrets | Easy |
| `pass08.py` | String cleanup methods (`replace`, `rstrip`) | Easy |
| `pass09.py` | Boolean conditions | Easy |
| `pass10.py` | Program flow around `random.randint`. A hint in the source says guessing isn't required. | Easy |
| `pass11.py` | Working with `datetime` dates and comparisons | Easy |
| `pass12.py` | Reading interpreter errors: syntax errors and type mismatches | Easy-Medium |

## Steganography: `Steganography/canvas.png`
- **Skill:** image steganography analysis, such as metadata inspection, looking at color channels and bit planes, and using tools like `zsteg`, StegSolve or Aperi'Solve.
- **Player gets:** a single 318×159 RGBA PNG.
- **How it's built:** no source image or embedding script is included.
- **Difficulty:** Medium

## Log analysis: `errorlogs/`
- **Skill:** log triage. Players cut through repetitive noise with `sort | uniq -c`, `grep` and `grep -v` to spot the one line that doesn't fit.
- **Player gets:** `error_log.txt`, 1,000 lines of simulated server errors: database connection failures, failed root logins, PHP syntax errors and out-of-memory errors. The log is generated by `err.py` and not committed.
- **How it's built:** `err.py` writes 1,000 lines, each chosen at random from a list of 10 message templates. One template is the flag (a placeholder until you set your own), so it is buried at random points in the log. The `range(1000)` loop count controls the log length.
- **Difficulty:** Easy

---

## Network forensics: `sharking/`
- **Skill:** traffic analysis with Wireshark, including exporting objects from HTTP traffic, and file-signature analysis for data that won't open as-is.
- **Player gets:** four `.jpg` files (`shark.jpg`, `shark(1).jpg`, `shark(2).jpg`, `shark(3).jpg`). None of them starts with a JPEG header, so they are pieces of image data rather than complete images. The `(n)` suffixes suggest these objects were exported from a web traffic capture.
- **How it's built:** no capture file or build script is included (`Networking/pcap/` is empty).
- **Difficulty:** Medium

## Building / hosting the challenges

### Requirements
- Python 3.6+ (the scripts use f-strings)
- [PyCryptodome](https://pypi.org/project/pycryptodome/) for `Forensics/aes/aes.py` (`pip install pycryptodome`)
- A C compiler (`cc`, `gcc` or `clang`) to build the strings binary
- Standard Unix tools for players: `find`, `grep`, `file`, `tar`, `md5sum`/`md5`, `strings`, `sha256sum`. `exiftool` is recommended for the photo challenges.

### Step 1: set your own flag values in the scripts, then run the build scripts
The repository ships with placeholder flags only, and the files players receive for most Forensics, Linux commands and log-analysis challenges are **not committed**. Before an event, edit the flag values, then build (Step 2). Flags are set in:

- `Forensics/aes/aes.py`, `Forensics/stri.c` and `errorlogs/err.py` (`cybercamp{your_flag_here}`)
- `Linux commands/ctfmaker.py`, for both flag files (`CYBERCAMP{your_flag_here}`)
- `Linux commands/find/genereate.py` and `Linux commands/grep/generategrep.py` (`camp{your_flag_here}`)
- `Forensics/dictionary/dic.py`: the chosen password (a placeholder 8-letter word, marked with a comment)
- `Scripting-Programming/python/pass01.py` to `pass12.py` (`cybercamp{your_flag_here}`, or `CTF{your_flag_here}` in pass07). In `pass04.py` and `pass06.py` the flag is spelled out as a character or part list, and in `pass08.py` it is padded with extra `1`s; keep those mechanics when you substitute your flag.
- The `file` and `tar` challenges have no script: put your flag directly into their setup commands below.

### Step 2: build the generated challenges
Run each builder **from its own folder**, because the scripts write output relative to the current directory.

| Challenge | Command (run inside the folder) | Produces | Randomized |
|---|---|---|---|
| Flag hunt | `python3 ctfmaker.py` in `Linux commands/` | `ctf_challenge/flags/` and three printed tasks | No |
| `find` maze | `python3 genereate.py` in `Linux commands/find/` | `ctf_challengelevel2/` (100 dirs, 1 flag); edit `base_dir` and the flag file name to build Level 1 (`ctf_challenge/`) | Flag directory |
| `grep` | `python3 generategrep.py` in `Linux commands/grep/` | `challenge.txt` | Filler words, flag position |
| MD5 file match | `python3 md.py` in `Forensics/md5sum/` | `cybercamphashes/file1.txt` to `file10.txt` (replacing the committed sample) plus the target hash on stdout | File contents, chosen file |
| Dictionary attack | `python3 dic.py` in `Forensics/dictionary/` | `dictionary.txt`, `hashed_password.txt` | Decoy words |
| AES | `python3 aes.py` in `Forensics/aes/` | Base64 ciphertext on stdout | No (fixed key and IV) |
| Error log | `python3 err.py` in `errorlogs/` | `error_log.txt` | Line order and frequency |
| Strings | `cc stri.c -o flag_finder` in `Forensics/` | `flag_finder` binary | No |
| tar | `echo 'cybercamp{your_flag_here}' > flag.txt && tar -czf flag.tar.gz flag.txt && rm flag.txt` in `Linux commands/tar/` | `flag.tar.gz` | No |
| `file` | `echo 'cybercamp{your_flag_here}' > cat.png` in `Linux commands/file/` | `cat.png` (text with an image extension) | No |

Replace `cybercamp{your_flag_here}` in the last two commands with your own flag. The Cryptography, photo geolocation, geocodes, Steganography and sharking challenges are static files, ready to hand out as they are. The Python scripting challenges are handed out as-is once their flags are set.

### Hosting notes
- **Destructive rebuilds:** `ctfmaker.py`, `genereate.py` and `md.py` delete their previous output directory (`shutil.rmtree` / `rm -rf`) before rebuilding. The other builders overwrite their output files. Run them in a disposable copy of the repo.
- **Record printed prompts:** `md.py` prints the target hash and `aes.py` prints the ciphertext without saving them. Copy them into your CTF platform when you build.
- **Build the `find` mazes before hosting:** neither maze is committed. Run `genereate.py` once for Level 2, and again with `base_dir` set to `ctf_challenge` and a non-hidden flag file name for Level 1.
- **Compile `flag_finder` for your target:** build it from `stri.c` on the machine or VM players will use.
- **Missing folders:** `Linux commands/file/` and `Linux commands/tar/` contain no tracked files, so they may not exist in a clone. Create them (`mkdir -p`) before running the setup commands.
- **Split player files from organizer files:** once you set your flags, the build scripts and source files (`aes.py`, `dic.py`, `ctfmaker.py`, `genereate.py`, `generategrep.py`, `err.py`, `stri.c`) contain answers in plain text. Give players only the generated artifacts. The `pass*.py` challenges include their flags by design, so treat them as practice rather than scored challenges.
- **Don't commit your build:** generated files and scripts edited with real flags would spoil the challenges, so keep them out of any public copy of the repository.
- **Delivery:** static artifacts can be uploaded to any CTF platform (for example, CTFd). The Linux command challenges work best copied onto a shared Linux VM or container where players have a shell.

## Solutions are not included

This repository documents what each challenge teaches and how it was built, but it deliberately leaves out flags, keys, passwords, decoded messages and walkthroughs, so the challenges stay useful for future workshops. Flags in the scripts are placeholders, and generated files that held flags or answers are not committed. Instructors who need an answer key can build one from the flags they set and the build output before an event.
